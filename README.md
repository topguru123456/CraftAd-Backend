# Craftad API

NestJS + Prisma backend. Replaces the per-feature Supabase Edge Functions with a single deployable service.

## Stack

- **Runtime**: Node 20+
- **Framework**: NestJS 11
- **DB**: Prisma 6 → Supabase Postgres
- **Auth**: Supabase Auth as identity provider; this API verifies the FE's JWT (added in Step 1.3)
- **Validation**: Zod (env), class-validator (DTOs)
- **Deploy**: Cloud Run via Docker

## Layout

```
backend/
├── src/
│   ├── main.ts                ← bootstrap (env, CORS, Swagger, filters)
│   ├── app.module.ts          ← root module
│   ├── config/                ← typed env loader (Zod) + ConfigService
│   ├── common/
│   │   ├── filters/           ← global exception filter → consistent error envelope
│   │   ├── logger/            ← per-request log middleware
│   │   └── prisma/            ← PrismaService + @Global PrismaModule
│   ├── auth/                  ← JWT guard, @CurrentUser, @Public, /auth/whoami
│   └── health/                ← /health endpoint (@Public)
├── prisma/
│   ├── schema.prisma          ← single source of truth for public schema
│   └── migrations/            ← generated by `prisma migrate dev`
├── Dockerfile                 ← multi-stage prod image for Cloud Run
├── .env.example               ← copy → .env locally, never commit secrets
└── package.json
```

## Local dev

```powershell
cd backend
cp .env.example .env       # fill in values
npm install
npm run start:dev
```

Then visit:

- http://localhost:3001/health      → `{ "status": "ok", "uptimeSec": …, "version": "0.1.0" }`
- http://localhost:3001/api/docs    → Swagger UI

## Env vars

Every key in `.env.example` is validated at boot via [`src/config/env.schema.ts`](src/config/env.schema.ts). A missing or malformed value crashes the app with a list of every issue — no surprise 500s later.

For Step 1.1 you only need the **Runtime** + **Supabase** + **CORS** sections filled in. AI provider keys and dispatcher URLs become required in later steps.

## Database workflow

### First-time setup

1. Fill `DATABASE_URL` (pooled) + `DIRECT_URL` (direct) in `.env`. See `.env.example` for connection-string format.
2. Stop the dev server if it's running (Prisma can't swap engine binaries while Node has them open on Windows).
3. Apply the schema:
   ```powershell
   npm run db:migrate:dev -- --name init
   ```
   This creates `prisma/migrations/<timestamp>_init/migration.sql` + applies it to your Supabase Postgres + regenerates the Prisma client.
4. Verify in Supabase Studio: the `public.users` table should now exist with columns `id`, `email`, `created_at`, `updated_at`.

### Changing the schema later

1. Edit `prisma/schema.prisma`.
2. `npm run db:migrate:dev -- --name <descriptive_name>` — Prisma generates the SQL diff, applies it, and updates the client.
3. Commit both the schema change and the new migration folder.

### Production deploys

CI runs `npm run db:migrate:deploy` against the prod `DIRECT_URL` before starting the new container. Never edit schema in prod by hand.

## Auth

Every endpoint requires a valid Supabase JWT by default. The global `JwtAuthGuard` verifies the token (HS256 against `SUPABASE_JWT_SECRET`), rejects expired/missing/wrong-role tokens, and attaches an `AuthenticatedUser` to `request.user`.

```ts
@Get('me')
me(@CurrentUser() user: AuthenticatedUser) {
  return user.id;
}
```

Opt out for routes that don't need auth (health check, webhooks with their own shared-secret auth, etc.):

```ts
@Public()
@Get('hello')
hello() { return 'no token needed'; }
```

### Trying it with curl

1. Sign in via the frontend.
2. In the browser console: `(await supabase.auth.getSession()).data.session.access_token`
3. `curl -H "Authorization: Bearer <token>" http://localhost:3001/auth/whoami` → `{ "id": "...", "email": "..." }`

Errors are deliberately distinguishable:
- `Missing Authorization header` — no header
- `Authorization header must be "Bearer <token>"` — malformed
- `Token expired` — FE should silently refresh, not log out
- `Invalid token` — bad signature / wrong issuer
- `Token role is not authorized` — service-role or anon token reached us
